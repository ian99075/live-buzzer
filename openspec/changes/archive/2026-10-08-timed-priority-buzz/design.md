# Design

## Context

見 [proposal.md](proposal.md) 的變更原因。目前 `Classroom` 以單一 Node 程序的記憶體 Map 保存題目及每題學號的首次回答，第一筆有效回答在同步提交路徑立即成為 winner；教師經 REST／SSE 看全部回答，學生只看自己的 submitted。`SheetExporter` 取當下 winner 快照並以 Google Sheets API 覆寫固定 Case 1–6 的 C19–C24。這次變更跨越裁決、計時、角色投影、畫面及匯出，因此需要共同的狀態定義。

## Goals / Non-Goals

**Goals:**
- 在單一程序內以後端時鐘和同步狀態轉換裁定截止、順位與結算；並使教師端開放期間的暫定排序和最終遞補可追溯。
- 保留學生結果隔離、同學號同題去重、單次確認送出及固定 Google 寫入範圍。
- 用可注入時鐘與模擬 writer 驗證時間邊界、併發、排序、失格及再次匯出。

**Non-Goals:**
- 不加入資料庫、跨程序共享狀態、學籍驗證、自動判定回答正確性或自動同步 Sheet。
- 不讓學生看到自己的優先權、其他學生資料、勝負或名次；不改變「回答_學號」與 Case 儲存格映射。

## Decisions

### 1. 題目生命週期及計時

每題保存 `durationSeconds`、`status`、剩餘毫秒及伺服器截止時刻；狀態轉換為 `draft -> open -> paused -> open`，或 `open/paused -> settled`。`start` 僅適用 draft，`pause` 僅適用 open，`resume` 僅適用 paused，`stop` 是提早結算；settled 為終態。預設 60 秒且只允許在 draft 修改 1–3600 秒的整數。這讓既有不傳秒數的建題請求仍可建立題目，同時教師畫面提供明確的秒數欄位。

後端用單調時鐘計算到期與暫停剩餘時間，避免系統時鐘校正導致比賽時長突變；對外提供可顯示的 `deadlineAt`、`remainingMs`、`serverNow`。到期排程負責主動結算並通知瀏覽器；每次提交、控制操作及投影讀取也先同步處理已到期題目，因此即使排程延遲，截止後抵達的提交仍不會被接受。多題同時到期時，按截止時刻再按 Case 號處理，讓跨題得標計數有穩定的先後順序。狀態檢查、到期結算、提交寫入及排名更新的關鍵區段維持同步，不插入 `await`。

考慮過以前端倒數結果作截止判斷，但裝置時間與網路延遲不能作為裁決依據；也考慮過每秒向所有客戶端推播，會造成不必要的流量。畫面以後端傳來的期限與時間基準在本機繪製秒數，只有狀態改變才由 SSE 通知。

### 2. 提交、即時排序及固定結算

每份保存的提交使用獨立 `submissionId`、學號、回答、伺服器接受時間、每題遞增且唯一的接受順序，以及失格標記。學號仍由學生工作階段取得。有效提交只在 open 且未到期時加入；同學號同題原始提交永久占用該題去重鍵，即使後來失格也不可重答。

開放或暫停題目的每位非失格候選人，其優先權計數是「其他已結算、未刪除題目中，目前有效得標者為該學號的題數」。排名使用 `(先前得標次數由少到多, 本題接受順序由早到晚)`。新增提交、其他題目結算、得標者失格遞補或已結算題目刪除時，重新計算尚未結算題目的排序；教師快照標示暫定第一名及每人的當前計數。這直接滿足開放期間觀看目前排行的需求，不等到結算才首次排序。

結算時將當下計數與完整候選順位固定為該題的結算快照，最前方的非失格候選人成為唯一最終得標者。之後其他題目的得標變動不回頭重排此題；若本題得標者失格，依本題固定順位往後找第一個未失格者。失格操作以提交 UUID 定位，教師確認後只標記失格，不硬刪回答；所有候補失格則 winner 為 null。系統不自動判斷亂答，只有具權限教師可執行。考慮過直接刪除提交，但那會讓同一學號重新送出，且使教師無法查核為何發生遞補。

### 3. 角色投影與即時事件

教師題目投影加入時限、狀態、完整提交、失格標記、優先權計數及順位；未結算時 `provisionalLeader` 可有值但 `winner` 為 null，結算後反之。教師總覽和單題詳情分別呈現剩餘時間、暫定第一名或最終得標者、排名和全部回答；失格提交仍可見但排除候選。SSE 到達時沿用現有局部更新方式，不覆蓋正在編輯的題目或回答草稿。

學生投影只含 open／paused 題目及自身 submitted、題目狀態與計時資訊；paused 卡片留在畫面並禁用送出，settled 卡片移除。學生不接收教師排名欄位、失格原因、跨題得標次數或任何人數。`serverNow` 用於校準畫面倒數，但 SSE 去重以不含變動時鐘的穩定公開欄位比較，避免僅因教師排名變動就向其他學生送出可觀察事件。教師與學生各自重連時都重取自己的完整投影。

### 4. 學生確認彈窗

`answer-card` 先驗證非空且未超長，按「搶答！」只開啟符合現有視覺樣式的確認對話框，文字節點顯示題目與凍結供預覽的回答。返回、Escape 或關閉視窗不呼叫 API，仍可改答案；按「確認送出」才凍結提交快照、鎖定該題並呼叫原 buzz API。若彈窗期間題目暫停、結算或本機倒數到零，確認按鈕失效並關閉彈窗；後端到期檢查仍是最終依據。網路失敗沿用同一份凍結回答安全重試，不再要求使用者重複確認。對話框要管理鍵盤焦點、焦點返回及多題卡片切換，不以原生 `window.confirm` 製作無法顯示完整回答的介面。

### 5. Sheet 匯出與已匯出紀錄

`SheetExporter` 僅從 settled 題目取得目前未失格得標者。每題在記憶體中追蹤本次課堂是否有「Google 已確認成功寫入」紀錄；下次手動匯出時，有新候補就對同一格寫入其 `回答_學號`，全員失格且此題之前已確認成功匯出就對該格以 RAW 寫空文字。從未成功匯出且沒有得標者的題目仍略過。清空成功後清除該題的待清空標記；刪除整題維持既有規則，不自動清除 Sheet。

匯出開始時同步建立包含題目 UUID、操作類型及固定格位的快照；成功且 `totalUpdatedCells` 與快照格數相符後，才更新本機已匯出追蹤。回應的 `writtenCount` 是本次更新格數，`clearedCount` 是其中清空格數。匯出期間保留既有管理鎖，新增失格操作也回 409；學生提交仍可進行，但新結算或回答不加入已建立的快照。教師確認清單明列覆寫及清空，暫定第一名不列入。仍使用既有服務帳號、Google Sheets API、RAW 及固定 C19–C24；不讓前端指定其他儲存格。

考慮過失格後立即同步 Sheet，但使用者指定由下一次教師手動匯出才覆蓋。Google 寫入成功但回應遺失時，後端不能確認遠端狀態；保留既有失敗回報與手動重試策略，不假稱寫入已完成。

### 6. 契約、測試與部署邊界

更新 `docs/openapi.json` 的題目狀態、時間欄位、教師暫定與最終結果、`pause`／`resume`／失格路由，以及匯出 `clearedCount`。學生 buzz 仍使用 202 `{"received":true}`，不藉回應透露是否有效或得標。新增 `node:test` 的可注入時鐘測試：截止前後、暫停／繼續、多題同時到期、併發去重、其他題目完成後即時重排、結算固定、失格候補、學生資料白名單、確認彈窗、寫入／清空及 Google 失敗重試。使用模擬 writer，不需要正式憑證；瀏覽器驗收檢查教師順位和學生彈窗、草稿與倒數。真實 Google 寫入只在使用者授權的指定 Case 範圍內執行，並按約還原；模擬通過不等於真實寫入已驗收。同網路操作已由使用者先前確認，本次仍維持單一 Node 程序及現有 LAN 設定，不把多副本部署納入範圍。

## Risks / Trade-offs

- [開放中順位可能跳動] → 教師端明示「暫定」，顯示每人先前得標次數與提交順序；結算後改為固定結果。
- [計時排程晚醒或瀏覽器時間不準] → 後端提交路徑先檢查單調時鐘並同步結算；前端倒數僅供觀看。
- [學號由學生自填] → 仍沿用課堂自報學號，無法防止冒用；不把優先權解讀成真實身分驗證。
- [重啟遺失課堂與已匯出追蹤] → 沿用既有記憶體生命週期；Sheet 已寫入的值仍在，但重啟後不推測先前匯出紀錄。
- [Google 回應遺失] → 不將結果標成已確認，允許教師檢視 Sheet 並重試固定儲存格；不宣稱跨系統 exactly-once。
- [舊 API 用戶端] → 建題省略時間採 60 秒預設，其餘狀態及回應變更在 OpenAPI 標示；正式教師與學生頁面同版更新。

## Migration Plan

此 change 在實作、測試及 OpenSpec Verify 前維持為進行中；不得先同步或歸檔。部署新版時應於課堂間停止原單一 Node 程序並啟動新版，因目前資料本就僅存記憶體，舊題目與工作階段不遷移；既有 `.env`、Google 憑證與 Sheet 格式不需更換。若需回退程式，先停止新版服務，再使用舊版；已由新版匯出的 Sheet 儲存格不會隨程式回退，教師需依實際表格狀態人工處理。
