# Proposal

## Why

目前每題第一份有效回答會立即成為第一名，教師無法設定作答時限，也無法用過往得標次數調整機會；誤觸送出或亂答者占位後，現有流程亦無法在同題遞補。這次變更讓教師在倒數期間看見可解釋的即時順位，並於結算後修正失格結果。

## What Changes

- 教師新增題目時設定各題倒數秒數；開始後倒數，支援暫停、繼續及提早結算。倒數到零自動結算，結算後鎖定該題，不再用原「停止後重開」流程。
- 教師端在題目開放期間顯示全部有效回答、伺服器接收順序、先前有效得標次數、目前順位與暫定第一名。順位先比較其他已結算題目的有效得標次數，再比較本題伺服器接受提交的順序；相關得標結果變動時即時重算，結算後固定排序與唯一得標者。
- 教師可對亂答者取消資格，保留教師可見的失格紀錄並由固定順位的下一位遞補；失格者不得再答同題，學生端仍不取得勝負、名次、其他人資料。
- 學生按「搶答！」後先確認題目與回答；只有按「確認送出」才發出請求並鎖定該題。取消可回去修改，確認彈窗不暫停倒數。
- Google Sheet 只匯出已結算的有效得標者，維持 Case 1–6 對應 C19–C24 與「回答_學號」。失格遞補不自動寫入；教師下次手動匯出時覆寫。若本次課堂先前已成功匯出該 Case，後來全員失格，下一次匯出清空該格；其他無得標者的格不動。
- **BREAKING**：原本「第一筆提交立即固定第一名」及「停止後可重開並保留第一名」的行為改變；教師與學生題目 API／SSE 投影需增加計時狀態，教師控制與失格操作需新增契約。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `question-management`：題目倒數與生命週期、即時優先排序、結算、失格與遞補，以及教師 API 和畫面。
- `private-buzz`：學生確認送出、截止時間與去重、學生可見計時資訊、後端優先排序及結果隔離。
- `sheet-export`：僅輸出已結算得標者、下次手動匯出覆寫候補，以及有匯出紀錄而全員失格時清空舊格。

## Impact

- 後端課堂狀態與裁決：`src/classroom.js`、`src/projections.js`、`src/events.js`、`src/routes/teacher.js`、`src/routes/student.js`。
- 前端：`public/js/teacher.js`、教師題目與回答元件、`public/js/student.js` 與學生回答元件，以及對應 HTML/CSS。
- 匯出：`src/sheets.js` 的快照與清空資料；仍使用既有 Google Sheets API、服務帳號與固定寫入範圍。
- 契約與驗收：`docs/openapi.json`、`tests/`、操作與驗收文件。課堂狀態及匯出紀錄仍僅在單一 Node 程序記憶體，不加入資料庫。
