# Design

## Context

參見 [proposal.md](proposal.md)。本 change 的題組模型已實作，後續新增的編號與登出規則以目前程式為基線：`Classroom` 以 `questions`／`caseIndex` 管理 Case 容器與獨立題目 UUID；教師建題仍手動傳 `caseNumber`，刪題不遞補。`SheetExporter` 依目前編號計算格位，以 `confirmedExport` 與 `pendingClear` 在記憶體追蹤已寫入結果。教師端尚無登出按鈕，工作階段只在到期或服務重啟時失效。目標工作表的 D19:E19 合併，以及 Case 7 起的列標記與原有內容，仍要求匯出先讀取結構並安全重試。

## Goals / Non-Goals

**Goals:**

- 保留現有單題 ID 路由與同步裁決區段；轉題組時不重置已開始的題目。
- Case 與小題編號始終連續；題目 UUID 穩定，顯示／匯出座標可隨刪題改變；輸出前由後端產生可核對的預覽。
- Sheet 結構調整可在逾時、回應遺失及重試時安全辨識，避免重複插列。
- 教師登出只撤銷目前工作階段，不清空課堂或影響其他連線。

**Non-Goals:**

- 不持久化課堂題目、回答、工作階段或匯出待辦；重啟後不從 Sheet 還原課堂。
- 不依據人工改動過的任意試算表版型猜測新的 Case 座標，也不同步其他分頁。
- 不新增資料庫、Apps Script 或多程序裁決。

## Decisions

### 1. Case 容器與可搶答題目分離

`src/classroom.js` 以 `Map<caseNumber, caseRecord>` 保留 Case 容器，另以穩定 `groupId` 定位題組；`questions` 仍以 UUID 索引每個可搶答題目。新的 Case 號由單一同步方法按目前容器數量分配 `size+1`；題組小題由目前有序 ID 長度分配下一號。建立與刪除均在無 `await` 的同步關鍵區段完成，避免兩位教師同時建題拿到同號。刪除單題或整組後，對後續 Case 依序減一並重建 `caseIndex` 鍵；刪除小題後，依剩餘 `questionIds` 重編 `partNumber`。刪掉最後小題時移除空容器，再壓縮後續 Case。保留未刪題目的 UUID、題組 ID、計時、提交、順位、得標與失格狀態；題號僅是可變顯示／匯出位置。按 UUID 的搶答與教師題目操作、按 groupId 的題組操作仍指向原對象，不會落到同位置的新題／題組。

選擇穩定 UUID、可變題號，是為了讓單題轉組或刪題遞補後，學生送出狀態、計時及過期請求仍由原題 ID 判斷。未採用刪除並重建題目 ID 的方案，因為會遺失開放題目的計時與回答，也會讓舊請求誤落到新題。

### 2. 轉換僅改容器與標籤，不重新裁決

`POST /api/teacher/questions/{id}/convert-to-group` 只接受單題 ID 與題組標題；在同一同步操作內核對輸出鎖及目前 Case，將原題 `partNumber` 設為 1、容器改 group，下一小題從 2 開始。不修改 `deadlineMono`、`deadlineAt`、`remainingMs`、`submissions`、`finalRanking`、`winnerKey` 或已確認輸出座標。草稿、開放、暫停及已結算狀態均可轉。追加的小題一律 draft，須單獨按開始。開放中轉換或新增小題後推送 SSE；前端按 UUID 保留草稿、倒數與已送出狀態。

題組標題僅作識別，仍經 1–2000 字文字驗證及 `textContent` 顯示。小題內容、倒數與回答沿用既有上限。API 以欄位白名單拒絕前端指定小題序號、勝負或匯出座標。

### 3. 每小題獨立裁決，教師和學生投影分離

`all()` 按 Case、partNumber 排序；每個小題維持自身同步的截止、去重、接受順序與唯一得標者。`priorWins` 遍歷所有**其他**已結算且目前仍有效的題目，因此 1-1、1-2 各得標一次就是兩次；同組 1-1 結算或失格時，仍開放的 1-2 重新排行。若多題同時到期，沿用確定的 Case／小題順序逐一結算，避免事件迴圈排程使結果不穩定。已結算小題保留固定順位。

`src/projections.js` 的教師投影包含穩定 groupId、目前 Case／小題號及全部回答與得標資訊，學生只拿目前公開標籤、題目、計時與自己的 `submitted`。刪題改號後發布 SSE，教師導覽按更新後的 Case／小題號排序；學生端按 UUID 保留草稿、確認彈窗、倒數與已送出狀態，只更新標籤，不重新建卡。題組相關操作改以 groupId 路由定位，仍在大題頁；未開放的新增小題不出現在學生清單。

### 4. 匯出計畫由後端產生，座標和清空按儲存格追蹤

`src/sheets.js` 仍以目前 Case N 的列 `18+N`、小題 k 的欄 `C+(k-1)` 計算 A1 座標；單題視為 k=1。後端 `exportPlan` 依當前題號與本次課堂的輸出紀錄產生將覆寫／清空的座標；前端不自行推算。教師預覽提醒可能發生局部解除合併，實際範圍以匯出時讀取的 Sheet 現況決定。只有 settled winner 或本次課堂已確認匯出、如今須清空的座標進入一般快照；暫定領先者不進入。

以按座標追蹤的「本次課堂已確認寫入」帳本取代初版逐題 `confirmedExport`／`pendingClear` 清空判定，並保存未確認回應的批次與其預期值。帳本本身保留受影響題目的原座標，無須在每次改號時新增臨時清空紀錄；重編號後以目前所有已結算有效得標者建立新座標結果，再將帳本中不再由有效得標者佔用的舊座標列為清空。若新舊題目碰到同一座標，當前得標者覆寫優先；若當前題目尚未結算或無得標者，舊值清空。成功確認整批寫入後更新帳本，重試失敗時保留待處理座標。建立、刪除、改號與失格均不直接連線 Google；匯出期間沿用 `store.exporting` 鎖定教師結構操作，其他開放小題可繼續收回答。

若 Google 值更新逾時或回應遺失，下一次手動匯出先處理保留的未確認批次：讀取該批次涉及的格位，僅對可確認為該批次寫入值的過時格位清空，其他格位依目前題目結果覆寫或保持；不能確認時回報錯誤，不猜測清除。這避免「可能已寫入但未標記成功」後又改號時留下孤兒答案，也避免清除未被本系統觸及的原值。課堂重啟仍會失去記憶體帳本，與既有不從 Sheet 還原的限制一致。

### 5. Google 結構變更與值寫入分階段，重試先讀結構

第一次需要 Case 7 以上且尚無擴充列時，Google writer 先讀指定分頁的 `sheetId`、合併範圍及本應用的列標記。結構請求使用 `spreadsheets.batchUpdate`：在原第 25 列之前 `insertDimension` 所需列數；以相鄰 Case 列作格式參考、在 B 欄標示 Case N，並對每一新列建立綁定該列的 developer metadata。若目標輸出格落在合併區，先讀完整合併範圍，再用 `unmergeCells` 解除該範圍；不改與輸出無關的合併。結構請求依序處理並以原子批次提交。之後以既有 `values.batchUpdate`、`RAW` 寫入或清空各指定格，繼續檢查 `totalUpdatedCells`。

每次匯出之前重新讀取列標記及相關合併狀態：已存在的 Case 7+ 列只覆寫值，不再插入；連續建立至 Case 10 而只匯出 Case 10 時，一次建 7–10 四列。刪題使目前最高 Case 下降後，保留先前插入的列、B 欄 Case 標籤與 metadata 作為可重用容量，不執行實體刪列；舊 Sequence 依座標帳本清空。若結構批次已成功但回應遺失，重試由列標記得知已插入；若結構狀態不一致或原內容將被錯位，報錯供教師檢查。若結構成功而值更新失敗，下一次依標記繼續寫值。Google 的 `spreadsheets.batchUpdate` 處理插列、解除合併及 metadata；`values.batchUpdate` 以 RAW 覆寫或清空並核對更新格數（[結構批次](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate)、[值批次](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchUpdate)）。

列擴充標記位於 Google Sheet 的結構 metadata，不是課堂資料庫；Node 重啟後仍能判斷此前是否插過 Case 列，但題目及待清空紀錄依既有規則清空。Google 憑證、存取權杖與原始錯誤不出現在投影或日誌。這裡採用 metadata，而非只看 B 欄文字，是因為人工文字可被改動且不足以安全判定重試是否已插列。

### 6. API／文件與驗證邊界

教師 `POST /api/teacher/questions` 與 `POST /api/teacher/groups` 的請求白名單移除 `caseNumber`，回應由後端給予實際編號；若並行建立使彈窗預覽過期，以回應為準。題組建立與單題轉組回傳穩定 groupId，`PATCH`、`DELETE` 題組與追加小題改用 `/api/teacher/groups/{groupId}` 路徑；舊數字路由拒絕，避免改號後錯改別組。教師登出採 `DELETE /api/teacher/session`：`src/auth.js` 刪除目前 token 的雜湊條目，回應設同名、相同 Path 與安全屬性且 `Max-Age=0` 的 Cookie，`src/events.js` 立即結束該 token 的教師 SSE；其他 token、學生及 `Classroom` 不動。登出失敗時前端保留登入狀態並顯示錯誤，不誤稱伺服器已撤銷。新 API 與欄位同步到 `scripts/openapi.mjs` 並再產生 `docs/openapi.json`；既有按 UUID 操作搶答的路由不變。`README.md` 與 `openspec/config.yaml` 在 apply 時更新建題、連續編號、刪題對 Sheet 的影響及登出說明。

自動驗證使用 `node:test`、可注入時鐘與模擬 Google fetch／writer，涵蓋開放中轉換、同組優先權、刪題遞補與 UUID 穩定、Case 7 連續擴列與重用、移位後覆寫／清空、回應遺失重試、登出撤銷及學生投影隱私。瀏覽器驗收檢查建題號預覽、教師登出、題組遞補及學生畫面草稿／焦點保留。真實 Google 寫入是獨立驗收：需先備份且只在使用者明確授權的指定範圍測試，完成後還原；未經驗收不得宣稱真實 Sheet 結構已成功更改。實體區域網路跨裝置驗收另行記錄。

### 7. 教師端以 Case 資料夾呈現題組

以已確認的 `public/previews/grouped-teacher-layout.html` 為正式版型參考；預覽中的合成資料與模擬操作不搬入正式頁。`public/teacher.html` 將「建立題目」與「題目管理」做成獨立卡片，左側 Case 清單預設收合小題。點選題組進入大題頁，才顯示較大的題組標題、分界線、小題卡片及大題層級操作；點選小題進入其詳情及回答表，保留麵包屑返回題組。單題仍直接進入自身詳情，並保留轉題組入口。桌面版限制側欄網格的最小寬度，保留可見欄間距與右欄邊界；窄螢幕將欄位上下排列，避免兩塊卡片重疊。

建立題目／題組使用獨立 `dialog`，建立入口與彈窗標題顯示「新增題目/題組」，切換單題／題組時呈現對應欄位；移除可編輯的 Case 號，改為顯示「預計 Case N」，不把預覽值送給後端。題目管理的 Case 編號作為較小的輔助標籤，題目／題組標題作為較大的主要文字；文字過長時安全截斷，保留完整資料於詳情。題組的小題卡片將得標資訊拆成獨立區塊：狀態標籤、18px 學號、16px 回答文字各有層級；開放／暫停階段標「目前第一名 · 尚未結算」，結算後標「搶答第一名」，無回答時保留明確空狀態。小題詳情的結算後領先者標籤與無障礙名稱也使用「搶答第一名」，但不改裁決與匯出語意。題組頁右上角「新增小題」另開 `dialog`，顯示所屬 Case、預計小題編號，要求輸入 1–2000 字內容與 1–3600 秒倒數；實際編號仍以後端回應為準。題組標題修改與整組刪除只放在大題頁；小題詳情保留該題控制與回答。右上角登出按鈕只在已登入時顯示；成功後關閉教師 SSE、清除前端教師快照並回到登入畫面。

教師 SSE 更新以目前 `caseNumber` 與穩定題目／題組 ID 重新整理導覽、摘要與回答；正在輸入的彈窗不重建。所選題目若因前題刪除而改號，維持選取其 UUID；選取題組則維持 groupId；刪除目前所選小題時退回其題組，刪除整組時退回全部 Case。`groupControlsMap`、`expandedCases` 等前端狀態改以 groupId 為鍵，不能把舊 Case 號誤認為另一題組。教師端繼續使用後端 `exportPlan`。隔離瀏覽器驗收檢查桌面／窄螢幕、兩種彈窗、改號後導覽與選題、開放中追加、登出及 SSE 草稿保留；不因此觸發真實 Google 寫入。

## Risks / Trade-offs

- [原工作表有既存文字、合併及格式] → 只作用於教師預覽過的輸出格與必要完整合併範圍；先讀現況並拒絕不能安全定位的版型，真實測試前備份。
- [兩次 Google API 呼叫之間可能部分成功] → 結構修改帶列 metadata 並每次重讀；值更新可重試覆寫；僅值確認後回報本次成功。
- [刪題後新舊題目可能佔同一輸出格] → 以目前已結算有效得標者優先覆寫，對其餘本次課堂已寫入舊格清空；匯出前展示每格最終動作，失敗時保留帳本供重試。
- [值寫入回應遺失後又刪題] → 保存未確認批次的座標與預期值，下一次手動匯出先讀格位協調；不能確認值來源時停止，避免留下舊答案或誤刪其他內容。
- [人工同時插列或刪除 metadata] → 目標列標記或位置不一致即停止；Google 對與其他協作者同時編輯的最終表格狀態不提供應用層交易保證。
- [大題／小題號過大而超出工作表可用欄列或配額] → 先驗證數字與 Google 限制，拒絕不可表示或需過量擴充的請求，不寫入錯位座標。
- [課堂只在記憶體] → 保持單實例部署；重啟後題目、輸出座標帳本與待處理批次消失，已匯出 Sheet 內容不自動撤回。
- [登出與 SSE 競態] → 後端先撤銷 token 並結束其事件連線，前端收到成功再清除快照；另一登入裝置不受影響。

## Migration Plan

1. 在不承載實際課堂時套用後端建題 API 的破壞性欄位變更；既有教師頁必須與後端一併更新。現行課堂只在記憶體，部署重啟會清空尚未匯出的資料，應先完成既有課堂所需匯出。
2. 完成自動編號、刪題遞補、舊／新座標帳本、登出 API 與介面；更新 OpenAPI、README、設定背景並完成自動測試和教師／學生瀏覽器驗收。Case 1–6 仍對應 C19–C24，Case 7+ 仍按列擴充。
3. 如需真實 Sheet 結構驗收，先備份原工作表並取得本次明確授權範圍，記錄原值／合併／列次，再測試與還原；未獲授權時只保留模擬測試證據。
4. 回退程式可用既有版本，但新增的 Sheet 列和已解除的合併不會因程式回退而自動逆轉；須依備份人工復原。
