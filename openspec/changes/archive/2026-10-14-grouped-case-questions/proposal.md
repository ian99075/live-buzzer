# Proposal

## Why

本 change 提出前，每個 Case 只能有一道題，且介面與匯出固定在 Case 1–6，無法在同一大題下讓 1-1、1-2 等小題各自搶答，也無法處理第七題以後。題組版型完成後，教師又確認題號應由系統連續分配、刪題後自動遞補，且需要明確登出入口；同一 change 納入這些後續規則，使畫面題號、搶答資料與 Google Sheet 對位一致。

## What Changes

- 教師建立單題或題組時只填內容、題組標題與倒數秒數；後端從 Case 1 起連續指派大題號，不由前端輸入題號，也不限制為六題。題組 Case 顯示標題並容納依序編號的小題；大題本身不搶答，各小題各自倒數、提交、排序、結算及失格遞補。
- 教師可將既有單題（包括已開放或暫停者）轉成題組，原題保留 ID、計時與全部回答，成為 1-1；後續小題以草稿追加，教師再逐題開放。已結算單題也可保留結果轉換，無須重判。刪除大題或小題後，同層後續題號立即向前遞補；新題接在當前連續編號之後，既有題目的 ID、計時、回答與結算結果不因改號而重建。
- 教師端採用已確認的分層版型：建立題目／題組與題目清單分為獨立區塊，清單先顯示可展開的 Case；題目或題組標題比 Case 編號醒目。題組頁以較大的大題標題、分界線及小題卡片呈現，結算後的「搶答第一名」與尚未結算的「目前第一名」須清楚可辨；回答文字比原版更大，但仍小於學號。新增小題、改題組標題、刪除整組只在題組頁操作，小題詳情只提供該小題控制與回答。建立題目／題組與在題組中新增小題均使用彈窗，後者要求填寫小題內容及 1–3600 秒倒數，再確認建立。
- 每個已結算且仍有效的小題得標各計一次優先權；教師與學生介面依 Case 與小題編號辨識題目，學生端仍只看到自己的送出狀態。
- 匯出時，單題及 1-1 寫入 C 欄、1-2 寫入 D 欄、1-3 寫入 E 欄，Case N 使用第 18+N 列。首次匯出 Case 7 以上時，後端在原工作表 Case 區插入所需列；有題組的列僅解除實際輸出格必要的合併，允許覆蓋該輸出位置既有內容，其他版型盡量保留。刪題改號後，下次手動匯出以新座標覆寫有效得標者並清空本次課堂已確認匯出的舊座標；既有擴充列保留供後續重用，不因刪題自動刪列。
- 教師端右上角顯示「登出」，操作成功即撤銷目前教師工作階段、關閉該工作階段的即時連線並返回登入畫面；其他教師工作階段、學生及課堂資料不受影響。
- **BREAKING** 教師／學生題目投影、教師建題與新增小題 API、匯出預覽及 OpenAPI 合約需加入題組結構；建題 API 不再接受教師指定的 `caseNumber`，題組操作改以穩定題組 ID 定位，並新增教師登出 API。既有以題目 ID 操作搶答的路由語意保持為「可搶答的單題／小題」。原固定 Case 1–6 與 C19–C24 規則改為可擴充對應。

## Capabilities

### New Capabilities

無；題組是既有題目管理、私人搶答與 Sheet 匯出能力的擴充。

### Modified Capabilities

- `question-management`: Case 容器與小題管理、單題轉題組、連續自動編號及刪題遞補、教師登出、分層介面與各小題控制／監控。
- `private-buzz`: 小題獨立提交、優先權計數、改號後保留原題提交狀態，以及學生題組顯示與隱私。
- `sheet-export`: 小題橫向映射、Case 7 以上列擴充、局部解除合併、改號後新舊座標協調、重試與清空。

## Impact

影響 `src/classroom.js`、`src/auth.js`、`src/projections.js`、教師／學生路由與 SSE、`src/sheets.js`、`public/` 介面元件、`scripts/openapi.mjs`、`docs/openapi.json`、相關測試與 `README.md`／`openspec/config.yaml`。維持單一 Node 程序記憶體模型與既有 Google Sheets 服務帳號；不新增資料庫或 Apps Script。真實 Sheet 結構變更只在教師明確匯出時發生，實作驗收須使用備份及獲授權的測試範圍。
