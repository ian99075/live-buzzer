# Design

## Context

參見 [proposal.md](proposal.md) 的 Why。提案當時，`src/classroom.js` 以新增順序分配連續 Case 號，刪題會重排；`src/sheets.js` 從 C19 算出格位並在 Case 7 起插列；`src/projections.js` 在教師 SSE 快照中同步附帶固定座標匯出計畫。教師頁當時提供手動建題與改題彈窗。本 change 將這些行為換成 Sheet 佔位符模型。課堂資料仍僅在單一 Node 程序記憶體中；服務帳號憑證只留在伺服器。

提案當時對新表 `1X7YNIcyvPMsbUnTuBdJ5lwmkZmIHj2-wO-S7CdpEwo0` 的「學習單」分頁做唯讀檢查：`$q_1_1$`／`$q_1_2$` 當時在 C5／C6 的格內文字，答案鍵在 H5／H6；`$q_2_1$`／`$q_2_2$` 在 C8／C9，答案鍵在 H8／H9；`$q_3$`／`$q_4$` 在 C11／C13，答案鍵在 G11／G13。當時題組沒有獨立標題欄，題目與答案格均無佔位符備註。教師決定自行把六個 q 鍵移至原題目格備註。後續唯讀檢查已解析六個題目鍵及六個答案鍵；真實答案寫入權限仍未驗證。

## Goals / Non-Goals

**Goals:**
- 讓來源鍵成為穩定題目身分；單題獨立運作，題組共用一次倒數、提交、排名與第一名，角色投影依權限分離。
- 匯入只讀 Google Sheet，失敗不變更課堂；重匯只更新草稿文字、新增未開始題組的來源鍵，已開始題組出現新小題時整批拒絕。
- 匯出只改動教師確認、目前仍有唯一答案鍵的格位；重試能辨識答案格的備註。
- 學生在題目結算後看到該題目前有效搶答第一名的學號及 `G` 組別，失格遞補後與教師端一致。

**Non-Goals:**
- 不在系統內編輯 Sheet 題目文字、建立佔位符或自行插列／解除合併。
- 不新增資料庫、Apps Script、公開部署或對學生顯示開放中的順位、其他候選人及任何人的回答。
- 不以重匯復原服務重啟前的學生回答或自動清理上一堂課的答案。

## Decisions

### 1. 解析與驗證後一次套用匯入

以後端設定的 Sheet ID、分頁與既有 Google 授權讀取儲存格值、備註及合併資訊。只從題目格**備註**讀正規 `$q_N$` 或 `$q_N_M$`，同格 trim 後文字須為 1–2000 字元；題目文字若仍包含 `$q_...$`，報出格位並要求教師手動移到備註，不自動寫 Sheet。N、M 為無前導零的正整數；答案鍵 `$a_N$`／`$a_N_M$` 可在儲存格文字或備註中。每個 q 鍵及匹配 a 鍵均須唯一，答案格不可同時承載兩個鍵；同一 Case 不得同時有單題及小題。驗證整張表完成後，才同步更新課堂 Map 並發送一次教師／學生 SSE。任何格式錯誤或遠端讀取錯誤均保留原狀。

替代方案是由系統在首次匯入時自動搬移 q 標記；這會使原本只讀的匯入改成可能寫入題目格，故依教師選擇採手動搬移。逐格邊讀邊建立題目會在發現重複鍵前留下半套題目，也不採用。讀取整張表需設合理的格數與回應大小上限；超限報錯，不猜測未讀格位。

### 2. 對來源鍵建立穩定索引，刪除不重排

在課堂記憶體中維持 `q_1_2 -> 小題 ID` 之類的來源鍵索引；`caseNumber`、`partNumber` 從鍵解析，永不按陣列位置改號。題組以穩定 groupId 建立容器，標題為「題組 N」，以來源鍵順序排序小題；共用的狀態、倒數、提交集合、固定結算順位與一位第一名只存於題組，提交內按小題來源鍵保存所有回答。單題保留既有題目模型。題組開始後鎖定小題集合，避免歷史提交缺少新欄位；重匯若發現該題組新增來源鍵，回 409 並整批不變更課堂，不能部分匯入其他 Case。未開始題組可增量加入小題。刪除只移除本堂課資料與索引；下次匯入重新出現時建立新 ID。Case 1 已是使用中單題而 Sheet 改成題組鍵時先回報衝突，不暗中轉型。已開始來源鍵保留內容及狀態；draft 更新文字但保留共用倒數。來源暫缺的既有鍵保留並警示。

替代方案是沿用連續編號、另存原題號供匯出；兩套號碼會在刪題後分歧，因此不採用。

### 3. 教師 API 與投影分工

`POST /api/teacher/questions/import-google-sheet` 無請求體，回傳新增、更新、保留數及警示；單題的 `PATCH /api/teacher/questions/{id}` 與題組的 `PATCH /api/teacher/groups/{groupId}` 只收 draft `durationSeconds`。題組控制採 `POST /api/teacher/groups/{groupId}/{start|pause|resume|stop}`，整組失格採 `POST /api/teacher/groups/{groupId}/submissions/{submissionId}/disqualify`；原單題路由繼續服務單題，對小題 ID 發起單獨控制或失格回 409。題組開始後單刪小題回 409，刪整組仍可行。停用手動建題、改題文字、改題組標題、追加小題及轉題組路由。教師投影中題組呈現一份倒數／狀態、所有人的整組回答與一位目前第一名或結算第一名；小題內容只為題組內顯示及匯出對應。教師頁秒數設定留在草稿單題／題組，SSE 更新保留未送出的秒數和焦點。學生投影只提供純題目文字、自身送出狀態及結算後第一名身分，不暴露佔位符、格位、開放中順位或其他人的回答。OpenAPI 與 API 同步更新。

### 4. 結算後的學生結果投影與畫面

學生 `GET /api/student/questions` 與 SSE 共用受限投影，清單包含 open、paused、settled 的單題與題組，不含 draft 或已刪題；題組是一個清單項目，含有序的小題 ID／來源鍵與內容、一份計時與自己的整組 submitted。只有 settled 單題／題組附帶 `firstPlace: {studentNumber, groupNumber}` 或 `null`；未結算時完全省略。白名單不複用含答案、提交 ID 與順位的教師物件。結算、到期、失格遞補及刪題沿用全量 SSE 快照；重連取得最新結果，防止暫定領先者提早公開。

學生單題卡片維持原行為；題組卡片在 open／paused 時顯示所有小題回答欄、一份倒數及一個「搶答！」。每欄均非空才能進入一次確認彈窗，彈窗依小題順序列出全部回答；確認後送出一次整組 payload，立即鎖定整組。取消確認保留草稿。`POST /api/student/groups/{groupId}/buzz` 僅接受 `answers` 物件，以小題來源鍵為鍵，必須與目前題組成員完全一致；後端驗證全部非空、長度與總請求大小，學號／組別取自工作階段，成功受理仍固定回 202 `{"received":true}`，不透露是否入選。題組變為 settled 時關閉彈窗、移除送出控制，僅顯示一位「搶答第一名」的學號／`G` 組別或空狀態。等待提示按是否還有 open／paused 單題或題組判定；其他開放卡片的草稿與焦點不因 SSE 更新重建。文字以 `textContent` 呈現；OpenAPI 用條件 schema 表達 settled 才有 firstPlace。

學生頁現有 `#waiting` 緊鄰 `#answer-list`，後者的 `gap` 只分隔題目卡片，沒有分隔等待面板與第一張結算卡。版面以相鄰且可見、清單非空的條件式 CSS 加上區塊間距：桌面 28px、手機斷點（≤560px）至少 20px；保持正常文件流，不用負 margin、固定高度或絕對定位。等待面板隱藏或清單為空時不加這段空白。保留學生卡片 ID 與現有 `render()` 更新方式，不重建卡片，以免 SSE 更新時清掉草稿或焦點。驗收需實測桌面與手機寬度下等待提示加多張結算卡、長題目與長學號，確認沒有遮擋、邊框貼合或水平溢出。

替代方案是建立獨立結果 API 或逐筆遞補事件，但會增加同步及授權邊界；既有快照足以處理多個單題／題組。學生登入仍是免密碼且學號為自填，公開學號只限已登入的同課堂學生，不視為對外學籍驗證。

### 5. 匯出計畫由目前 Sheet 產生並與確認綁定

教師開預覽時，後端讀取最新答案鍵格位及現值／備註，依已結算有效第一名與本堂課已確認匯出的鍵生成計畫。單題產生一格；已結算題組取**同一份第一名提交**的所有小題回答，各寫其 `$a_N_M$`，不得在小題間混用不同候選人；未結算題組一格也不寫。本堂課已匯出的整組若改由候補第一名取代，全部對應格覆寫；若全員失格或刪整組，清空先前已匯出的各格。預覽 API 回傳真正的 A1 格位、寫入文字、清空項及短期不透明 token；伺服器記憶體將 token 綁定教師工作階段、計畫摘要及到期時間。確認時重新讀 Sheet，重新計算格位與課堂快照並比較摘要；任一鍵移位、格值改變、題組成員或第一名改變則回 409，要求重新預覽。POST 不接收前端格位、答案或學號。

替代方案是在 SSE 教師快照中長期快取格位；Sheet 在匯入後可能移格，教師會確認舊位置，因此不採用。讀取最新 Sheet 增加一次 Google API 呼叫，但與手動匯出的頻率相符。

### 6. 答案值與備註同批寫入，保留定位

新答案格若文字為 `$a_N_M$`，第一次匯出以 Sheets `spreadsheets.batchUpdate` 的 `updateCells` 在同批請求寫入 `userEnteredValue.stringValue = 回答_G組別` 及 `note = $a_N_M$`；若已有其他備註內容，保留其文字並加入獨立的佔位符行。後續讀備註定位並只修改文字值。清空時同樣只清除文字，備註保留；未曾由本堂課確認匯出的格不清空。合併格只接受左上角作為答案鍵錨點，否則回報安全錯誤而不拆版。寫入前核對預期舊值，避免覆蓋人工後來改動。

舊版 `values:batchUpdate` 只能寫值，無法一同保存備註，因此須改用儲存格更新。維持純文字 `stringValue`，使以 `=` 開頭的回答不變成公式。若寫入回應遺失，保留未確認批次；下一次讀回鍵、格值與備註，能確認已寫才更新本堂課帳本，否則安全失敗。跨服務重啟無記憶體帳本，已存在的備註仍讓相同鍵可再次覆寫；不據此推斷上一堂課是否該清空。

### 7. 課堂與遠端操作互斥

匯入及匯出各自取得管理操作鎖，避免兩次 Google 請求或教師改題／失格在遠端等待期間交錯；開放題與題組的學生提交維持同步截止與去重區段，遠端 I/O 不放入裁決區段。整組答案一次驗證、一次寫入記憶體，不容部分提交；排序以同組已結算且仍有效的**其他單題／題組**第一名次數優先，再依整組提交接受時間排序。開放期間教師可見即時排行；結算時固定順位與唯一第一名。取消整份提交後按固定順位遞補；同題失格學生不可重送。匯出先凍結有效第一名快照，後來才結算的單題／題組留待下次手動匯出。鎖釋放後發送完整教師更新。服務僅能維持單一 Node 程序；多副本會破壞記憶體狀態與確認 token。

### 8. 題組秒數表單的局部排版修正

教師題組控制元件已在 `public/js/components/group-controls.js` 將秒數標籤、數字輸入框與「儲存／取消」按鈕列放在同一個 `.question-editor` 表單；目前共用樣式未明確隔開輸入框與操作列。Apply 時優先在 `public/css/app.css` 對題組控制區的編輯表單設定獨立的垂直排列與間距，讓輸入框維持容器內寬度，操作列可換行；窄螢幕必要時改成單欄或保持足夠按鈕寬度。避免用負 margin、絕對定位或固定高度掩蓋重疊，也不改表單提交、取消、秒數驗證、SSE 焦點保存與 API。

以隔離的模擬課堂在桌面及 390px 手機寬度打開草稿題組的「設定秒數」，檢查輸入框與按鈕的外框沒有相交或相貼、按鈕文字完整可讀、頁面無水平溢出，並實際操作取消與儲存。若較窄視窗有換行，仍須維持清楚的上下間距。

## Risks / Trade-offs

- [教師在 Sheet 刪除或複製題目格備註／答案格佔位符，導致格位歧義] → 解析整份表並要求每個鍵唯一；報錯時不做部分匯入或匯出。
- [提案當時六個 q 標記仍在題目文字中] → 匯入偵測並指出格位；由教師手動移至同格備註後重試，不讓匯入悄悄修改工作表。後續唯讀檢查已可解析六個題目鍵。
- [人工刪除已匯出格的備註，或把答案鍵放在合併格非左上角] → 不按固定座標猜測；顯示需修復的鍵與格位，修復後重新預覽。
- [預覽後 Sheet 或課堂結果改變] → 確認 token 比對最新計畫，409 時重新預覽；單次寫入前仍核對原值。
- [新表的真實答案寫入權限尚未驗證] → 分開記錄已完成的唯讀檢查與未執行的編輯驗收；未經指定格與還原方案授權，不在真實表上寫測試答案。
- [備註會隨人工搬動或複製格子而移動／複製] → 每次匯出重新掃描並驗證唯一性，重複時停下而不選其中一格。
- [舊設定與文件仍指向原 Sheet 或固定 C19] → 更新設定範例與操作文件，實際 `.env` 先備份再由部署者調整；不將憑證或實際密碼寫入版控。
- [結算後失格或斷線使學生仍看見舊第一名] → 失格後向所有學生發布最新白名單快照，斷線顯示連線狀態，重連讀回目前結果；不傳遞失格名單。
- [等待面板與結果卡片並存時相貼，手機版又可能被長文字擠出畫面] → 只在兩區同時可見時加入響應式間距，保持正常文件流與文字換行，於桌面及手機寬度各驗收一次。
- [舊模型以小題各自送出、倒數和結算，直接切換會留下不完整整組提交] → 此變更於課堂空檔重啟並重新匯入題目；記憶體資料不跨版本遷移，單題既有契約維持。
- [題組開始後 Sheet 增加小題使既有回答缺欄，或確認匯出時題組答案被改動] → 鎖定已開始題組成員，增量匯入整批 409；預覽 token 綁定完整成員與整份第一名答案快照。

## Migration Plan

1. 實作階段先完成佔位符匯入、匯出與學生結果公開的基礎，再用合成 Sheet 和記憶體課堂驗證題組完整回答、一次計時、優先權計一次、失格整組遞補、已開始題組新增小題整批拒絕，以及同一位第一名逐小題匯出；教師／學生 UI 與 OpenAPI 亦隨之更新。舊版逐小題匯出不代表新模型的題組結果。
2. 提案當時的遷移步驟：教師先備份新表題目格，將 C5、C6、C8、C9、C11、C13 文字末尾的 q 標記分別移至**同一格備註**，格內只保留題目文字。後續唯讀檢查已能解析六個題目鍵；部署時仍須確認服務帳號對「學習單」的答案寫入權限，以及後端 `GOOGLE_SHEET_ID`、`GOOGLE_SHEET_NAME` 設定。服務重啟會清空本堂課記憶體，應在課堂空檔切換；從新表手動匯入題目後才開放搶答。
3. 用隔離模擬 writer 執行自動測試及本機瀏覽器驗收，包括學生多小題一次確認、教師整組控制與第一名、候補後整組匯出預覽。真實 Google 寫入須另取得指定格、備份與還原授權；若尚未取得，只記錄讀取成功與模擬寫入證據，不宣稱真實寫入已驗收。既有教室區域網路連線驗收不等於公開 HTTPS 部署驗收。
4. 若需回退，還原程式與原 Sheet 設定並在課堂空檔重啟；新表已寫入的答案與備註須由教師依備份人工核對，不能靠重啟撤銷。課堂記憶體資料無持久化，無法在新舊版本間遷移。
5. 結算結果公開以合成課堂資料驗證 GET、SSE、瀏覽器、題組失格遞補與 OpenAPI，無須真實 Google 寫入。回滾需在課堂空檔重啟；記憶體中整組回答不向舊版逐小題模型遷移。
