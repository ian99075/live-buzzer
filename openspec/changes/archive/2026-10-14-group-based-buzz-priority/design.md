# Design

## Context

參見 [proposal.md](proposal.md)。目前 `src/routes/student.js` 的登入只收學號；`src/auth.js` 的學生工作階段與 `src/classroom.js` 的提交、第一名及優先權也只保存學號。`src/projections.js` 由同一課堂模型分別產生教師完整快照與學生受限快照。`src/sheets.js` 將 `回答_學號` 同時用於預覽、Google 寫入及本機已確認格位帳本。題組 `groupId` 是題目容器 UUID，不能挪作學生組別。全部課堂狀態只在單一 Node.js 程序記憶體中。

## Goals / Non-Goals

**Goals:**

- 對同一學號建立本次程序內不可變的組別關係，保留每題每學號首次回答與單一第一名。
- 讓教師看到每份回答的組別及同組優先權，維持學生端的結果隔離。
- 使匯出預覽、實際寫入、重試與已確認值使用完全一致的 `{題目}_回答_G組別編號` 格式。

**Non-Goals:**

- 不提供組別名冊、教師修改學生組別、學籍驗證或持久化。
- 不變更 Case／小題座標、工作表結構處理、搶答倒數或 Google 授權方式。

## Decisions

### 組別編號與首次登入綁定

學生頁面的組別欄接受十進位正整數文字，將前導零正規化後，登入 API 傳 `groupNumber` JSON 整數；後端再檢查它是安全正整數。`studentNumber` 維持修剪後的原字串，不轉成數字。`src/classroom.js` 增加本次程序的學號至組別對照；`src/routes/student.js` 在建立學生工作階段前同步查詢或綁定。首次綁定後，同學號帶不同 `groupNumber` 登入回傳 409，原工作階段和提交不受影響。工作階段同時保存學號與組別，重新整理時學生快照只回傳自己的身分。重啟程序時對照與工作階段一併清空。

選擇後端綁定，而不是只相信每次登入或搶答請求攜帶的組別，避免同一學號在課堂中途意外切換組別。組別沒有額外密碼或名冊，故這只能維持資料一致，不能驗證學生是否真的屬於該組。學生端顯示前規格化為 `G${groupNumber}`；題組 UUID 繼續使用 `groupId`，不與 `groupNumber` 混用。

### 回答、排序與取消資格

在 `src/classroom.js` 的每份提交上保存登入時固定的 `groupNumber`；`submissions` 仍以學號為鍵，故同組不同學號可以各自送出，同一學號仍只保留首次有效回答。保持提交、截止判定、去重與接受順序在同一同步區段，不加入 `await`。第一名仍可由既有 `winnerKey` 指向學號，再從該題的提交取得其組別。

開放或暫停題目的 `ranking()` 對每位候選人計算其他已結算題目目前有效第一名所屬組別的次數，以該次數及 `acceptedOrder` 排序；結算時凍結原本的 `finalRanking`。題組的每個小題獨立計一次。第一名取消資格後，沿固定順位遞補下一份有效提交；重新計算其他仍開放題目的組別次數，不回溯改動已結算題的順位。這沿用現有即時排序與結算模型，無須建立另一份可失同步的組別計數表。

### 角色投影與介面用語

`src/projections.js` 的教師 `submissions`、`provisionalLeader`、`winner` 增加 `groupNumber`；`priorWinCount` 保留 API 欄名以減少契約改動，但其數值明確改為「同組先前有效第一名次數」。學生登入回應、GET 快照及 SSE 僅增加自己的 `groupNumber`，各題物件與固定 202 回應仍不含其他學生或順位。`src/events.js` 仍依學號將個人狀態推送到對應工作階段，不依組別廣播其他人的狀態。

`public/student.html` 與 `public/js/student.js` 增加數字組別欄、登入驗證及自己的 `G` 標示。教師元件在回答表、第一名卡及題組小題摘要顯示 `G` 標示，欄名改為「同組先前第一名次數」；清理教師頁面可見的「得標者」「得標」字樣，保留「目前第一名」與「搶答第一名」的狀態區別。文字仍以 `textContent` 等安全 DOM API 呈現。內部 API 欄名 `winner` 或程式變數不屬於可見文案。

### Sheet 值與失敗恢復

在 `src/sheets.js` 集中組合單格字串：`{${question.content}}_${submission.answer}_G${submission.groupNumber}`。對每個已結算題目，匯出開始時擷取其當前完整內容與有效第一名提交，建立固定快照。相同格式化值供教師 `exportPlan`、Google RAW 寫入、成功後 `confirmedCells` 與不明結果的讀回比對使用；不以題組標題或可變 Case 編號代替單題／小題內容。教師在結算後改題目文字時，下次手動匯出用新內容覆寫相同格位。

保留現有座標、局部解除合併、Case 7+ 結構標記、待清空舊格、單次匯出鎖及 Google 回應確認。若第一名失格且沒有候補，沿既有帳本只清空本次課堂確認匯出過的格；如有候補，以其回答與組別覆寫。Google 失敗或結果不明時保留記憶體資料及原帳本狀態，依既有讀回／安全重試流程處理。前端仍不能指定 Sheet 範圍或替換後端快照。

### 契約與驗證

在 `scripts/openapi.mjs` 增加學生登入及快照的 `groupNumber`，教師提交與第一名身分的 `groupNumber`，更新欄位語義與 409 回應，再產生 `docs/openapi.json`。自動測試以合成學號／組別及模擬 Google writer 驗證登入綁定、同組個別提交、動態排序與固定順位、跨小題計數、失格遞補、隱私投影及精確匯出值；同時執行 API 合約與現有回歸測試。瀏覽器手動驗收分別檢查學生登入／送出及教師各視圖的 `G` 標示與用語。若需實際 Google 寫入，另依當次授權的指定格位測試並還原；自動測試與本設計不宣稱已完成真實寫入或實體區域網路驗收。

## Risks / Trade-offs

- [學生首次填錯組別後無法自行改正] → 登入畫面清楚顯示輸入的編號與 `G` 格式，409 提示此學號與先前組別不符但不揭露原組別；本次需求不設教師更正工具，重啟會清空整堂課資料，須事前確認。
- [免密碼學生可冒用他人學號及組別] → 保留現有部署邊界與教師監督；本變更只保證同學號的組別一致性，不宣稱真實身分驗證。
- [同時開放的題目會因其他題結算或失格而重排] → 教師顯示「目前第一名」，結算後改顯示「搶答第一名」並固定該題順位；學生不取得名次。
- [舊 Sheet 格位仍有先前格式的文字] → 本次課堂再匯出相同座標時以新格式覆寫；程序重啟後沒有舊課堂帳本，不能自動判斷或清除所有歷史格位。

## Migration Plan

部署新程式需重啟單一 Node.js 程序；既有學生工作階段與課堂記憶體狀態隨重啟失效，學生重新以學號及數字組別登入。Google Sheet 的既有內容不會因部署自動改寫，新格式從下一次教師手動匯出開始生效。若回退程式，同樣需重啟，之後的匯出可能恢復舊格式；已寫入 Sheet 的值不會自動還原。
