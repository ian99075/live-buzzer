## timed-priority-buzz 實作驗收（2026-10-08）

本次只使用合成學號、模擬 Google writer 與本機臨時 HTTP／Chrome；沒有使用 `.env` 憑證，也沒有寫入真實 Google Sheet。原始系統於 2026-09-23 的真實 Case 1 寫入與還原紀錄仍有效，但不等於這次新增覆寫／清空邏輯的真實雲端驗收。

- `npm test`：26 項通過、0 失敗；包含假時鐘到期與排程略早醒後重新安排、刪除開放題、暫停／繼續、多題同時結算、100 人雙題提交、即時優先排序、失格後開放題重排、結算後固定順位、失格遞補、學生 REST／SSE 欄位隔離、固定 C19–C24 RAW 匯出、候補覆寫、全員失格清空、匯出中另一題到期與失敗重試。
- 實際 Chrome 瀏覽器（本機測試服務）以 A／B／C 等合成學號操作：教師新增倒數題、暫停與繼續；學生草稿保留，取消與 Escape 確認彈窗均未發送 POST，鍵盤 Enter 確認僅送一份；逾時彈窗自動關閉且未送出；模擬網路失敗後重試發送同一份凍結回答，後端僅保存一份。
- A、B、C 都送出開放題後，其他兩題分別由 A、B 結算得標；教師畫面即時把開放題順序調整為 C、A、B。結算後取消 C 資格，A 遞補；模擬匯出顯示 `甲答_A`。再取消 A／B 資格，下一次模擬匯出以空文字清除該 Case。
- 另起瀏覽器情境檢查：教師未儲存編輯在另一題新增的 SSE 更新後，文字、焦點與游標位置仍保留；只有待清空格、沒有任何有效得標者時，匯出確認按鈕仍可使用並送出空文字。390 px 教師／學生畫面沒有橫向溢出；學生介面及 SSE 全程沒有名次、得標者或他人回答。
- 新版 `docs/openapi.json` 由 `scripts/openapi.mjs` 產生；路由、參照及新增欄位已由合約測試解析核對。2026-10-08 的正式 Verify 已完成，報告見 [timed-priority-buzz-verification.md](timed-priority-buzz-verification.md)；本 change 已同步主規格並歸檔。
- Verify 期間修正教師總覽倒數、回答接收序、學生空白回答提示與 OpenSpec 專案設定的舊先送先得敘述；另以隔離 Chrome 驗證這三處 UI 更新。正式服務未重啟，也未清除既有課堂資料。

## 真實 Google Sheets API 驗收（8.4）

驗收日期：2026-09-23。使用者明確同意測試「工作表1!C19」並還原原值。使用正式 npm start 與本機 .env 的服務帳號，沒有注入測試 writer。

- 檢視前後端路由、登入、同步搶答裁決、角色投影、SSE、匯出模組與介面流程；本輪未發現阻擋既定功能驗收的問題，沒有修改應用程式。
- 發現教師帳密原為空白，依使用者授權產生 teacher 與隨機密碼，僅保存在 .env；未輸出私鑰或密碼。
- Google API 唯讀存取 HTTP 200，確認原生 Sheet ID 與目標分頁。
- 正式頁面／資源 HTTP 200，教師登入成功；testMode=false。未登入匯出為 401，空課堂匯出為 0 筆。
- TEST001、TEST002、TEST003 依序提交 Case 1，均收到相同 202 received=true；教師 API 保留三份回答，第一名為 TEST001。TEST001 改答案重送不覆寫原回答。
- 學生 API 每題僅有 id、caseNumber、content、submitted，不洩漏第一名或其他人回答。
- 兩次呼叫正式教師匯出 API 均回 200、writtenCount=1、ranges=['工作表1'!C19]、testMode=false。
- 每次以 Google API 讀回核對 C19 的 userEnteredValue 為 stringValue「整合驗收_TEST001」。
- 每次核對所有已讀工作表的使用者輸入值、使用者格式、文字格式片段、註記、資料驗證、列欄資訊、工作表屬性及合併範圍；除了 C19 測試值外皆保持一致。
- 驗收後以限於 C19 的還原要求恢復原值，重新讀取快照與測試前一致；暫存備份及本機測試題目已清除。

本輪真實流程透過 HTTP API 驗收，非再次以瀏覽器逐按鈕操作。介面的實際瀏覽器驗收證據見前段。真實 Google 驗收只寫入獲准的 Case 1；Case 2–6 固定映射由自動測試及程式核對，未額外覆寫雲端內容。
